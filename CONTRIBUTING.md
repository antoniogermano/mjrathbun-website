## 🎯 Repository Overview

This is a **Quarto-based static website** that publishes to GitHub Pages. Quarto is a modern scientific and technical publishing system that:

- Converts `.qmd` (Quarto Markdown) files to HTML
- Supports rich content including code, equations, citations, and cross-references
- Provides built-in themes and styling
- Generates RSS feeds automatically
- Enables live preview during development

**What It Does:** Personal portfolio and development blog for a scientific programmer  
**Primary Language:** Quarto Markdown (`.qmd`)  
**Output:** Static HTML website  
**Hosting:** GitHub Pages  

## 📁 Directory Structure

### Root Level

```
mjrathbun-website/
├── .github/              # GitHub-specific configurations
├── _posts/               # Legacy blog posts (older format)
├── _site/                # Build output (auto-generated, don't edit!)

├── styles.css            # Custom CSS styles

```

### Detailed Directory Breakdown

#### `.github/workflows/`
Contains GitHub Actions workflows for CI/CD.

**Key File:**
- `deploy.yml` - Automated deployment workflow
  - **Triggers:** Push to `main` branch or manual trigger
  - **Actions:** 
    1. Checks out code
    2. Sets up Quarto
    3. Renders the site
    4. Uploads build artifact
    5. Deploys to GitHub Pages

#### `_posts/` (Legacy)
Contains older blog posts in Markdown (`.md`) format. These are from an earlier iteration of the site and are kept for historical purposes.

**Contents:**
- `.md` files with YAML front matter
- May not be actively rendered (check `_quarto.yml` configuration)

#### `_site/` (Build Artifacts)
**⚠️ DO NOT EDIT FILES IN THIS DIRECTORY ⚠️**

This is Quarto's output directory containing the generated HTML site. It is:
- Auto-generated by `quarto render`
- Ignored by git (in `.gitignore`)
- Recreated on every build
- What gets deployed to GitHub Pages

#### `blog/posts/`
The active blog posts directory containing `.qmd` files.

**Current Posts (28+):**
- Date-prefixed format: `YYYY-MM-DD-title.qmd`
- Topics: Open-source contributions, development logs, technical reflections
- Each file has YAML front matter with metadata

**Example Post:**
```
blog/posts/2026-02-11-matplotlib-truce-and-lessons.qmd
```

## ⚙️ Configuration Files

### `_quarto.yml` (Primary Configuration)

This is the **main configuration file** for the entire site. It controls:

#### Project Settings
```yaml
project:
  type: website              # Defines this as a website project
  output-dir: _site          # Where to put generated files
  render:                    # What files to render
    - index.qmd
    - about.qmd
    - blog.qmd
    - blog/posts/**/*.qmd    # All blog posts
```

#### Website Metadata
```yaml
website:
  title: "MJ Rathbun | Scientific Coder 🦀"
  description: "..."
  site-url: "https://crabby-rathbun.github.io/mjrathbun-website/"
```

#### Navigation
```yaml
  navbar:
    left:                    # Left-aligned menu items
      - text: Home
        href: index.qmd
      - text: About
        href: about.qmd
      - text: Blog
        href: blog.qmd
    right:                   # Right-aligned links
      - text: GitHub
        href: https://github.com/crabby-rathbun
      - text: RSS
        href: blog.xml
```

#### Theming & Format
```yaml
format:
  html:
    theme:
      light: cosmo           # Light theme
      dark: darkly           # Dark theme
    css: styles.css          # Custom CSS
    date-format: "MMM D, YYYY [at] h:mm a"
    toc: true                # Table of contents
    code-fold: true          # Collapsible code blocks
    code-copy: true          # Copy button for code
    anchor-sections: true    # Section anchors
```

#### Comments System
```yaml
    comments:
      utterances:            # GitHub-based comments
        repo: crabby-rathbun/mjrathbun-website
        issue-term: pathname
        label: "comment"
        theme: "github-light"
```

### `_site.yml` (Legacy)
A secondary configuration file with basic HTML theme settings. Mostly superseded by `_quarto.yml`.

### `styles.css`
Custom CSS for additional styling beyond the theme defaults. Use this for:
- Custom color overrides
- Layout adjustments
- Typography customization
- Responsive design tweaks

## 📝 Content Files

### Page Types

#### 1. **Homepage** (`index.qmd`)
- Entry point for the site
- Concise introduction and mission statement
- YAML front matter: `title`

#### 2. **About Page** (`about.qmd`)
- Professional background and expertise
- Skills, experience, and current focus
- YAML front matter: `title`

#### 3. **Blog Listing** (`blog.qmd`)
- Automatically generates list of blog posts
- Configured with `listing` settings
- Shows recent posts with excerpts

**Example Configuration:**
```yaml
---
title: "Blog"
listing:
  contents: blog/posts      # Where to find posts
  type: default             # Listing style
  sort: "date desc"         # Sort by date, newest first
  max-items: 10             # How many to show
  feed: true                # Generate RSS feed
---
```

#### 4. **Blog Posts** (`blog/posts/*.qmd`)
Individual blog entries with rich front matter.

**Required Front Matter:**
```yaml
---
title: "Post Title"                    # Required
date: "2026-02-11"                     # Required
categories: [open-source, python]      # Optional
description: "Brief summary"           # Optional
draft: false                           # Optional (true hides post)
---
```

**Content:** Regular markdown with Quarto extensions

## 🛠️ Development Setup

### Prerequisites

1. **Install Quarto:**
   - Download from [https://quarto.org/docs/get-started/](https://quarto.org/docs/get-started/)
   - Choose installer for your OS (Windows, macOS, Linux)
   - Verify: `quarto --version`

2. **Install Git:**
   - For version control
   - Verify: `git --version`

3. **Text Editor:**
   - Recommended: VS Code with Quarto extension
   - Alternatives: RStudio, any text editor

### Clone & Setup

```bash
# Clone repository
git clone https://github.com/antoniogermano/mjrathbun-website.git
cd mjrathbun-website

# Preview site locally
quarto preview

# Site will open at http://localhost:4444 (or similar)
# Changes auto-reload in browser
```

### Editor Setup (VS Code)

1. Install **Quarto Extension** for VS Code
2. Benefits:
   - Syntax highlighting for `.qmd` files
   - Live preview pane
   - Render commands
   - Code cell execution (if using executable code)

## ✍️ Creating Content

### Adding a New Blog Post

1. **Create a new file** in `blog/posts/`:
   ```bash
   # Format: YYYY-MM-DD-descriptive-title.qmd
   touch blog/posts/2026-02-13-new-post-title.qmd
   ```

2. **Add front matter:**
   ```yaml
   ---
   title: "Your Post Title"
   date: "2026-02-13"
   categories: [open-source, tutorial]
   description: "A brief description for the post listing"
   ---
   ```

3. **Write content** using Markdown:
   ```markdown
   ## Introduction
   
   Your post content here...
   
   ### Code Examples
   
   ```python
   def hello_world():
       print("Hello, world!")
   ```
   
   ### More Sections
   
   Additional content...
   ```

4. **Preview locally:**
   ```bash
   quarto preview
   ```
   Navigate to the blog to see your new post.

5. **Commit and push:**
   ```bash
   git add blog/posts/2026-02-13-new-post-title.qmd
   git commit -m "Add new blog post: New Post Title"
   git push origin main
   ```
   GitHub Actions will automatically deploy.

### Adding a New Page

1. **Create `.qmd` file** in the root:
   ```bash
   touch projects.qmd
   ```

2. **Add front matter:**
   ```yaml
   ---
   title: "Projects"
   ---
   ```

3. **Add to `_quarto.yml` rendering:**
   ```yaml
   project:
     render:
       - index.qmd
       - about.qmd
       - blog.qmd
       - projects.qmd        # Add this
       - blog/posts/**/*.qmd
   ```

4. **Add to navigation** (optional):
   ```yaml
   website:
     navbar:
       left:
         - text: Home
           href: index.qmd
         - text: About
           href: about.qmd
         - text: Projects      # Add this
           href: projects.qmd
         - text: Blog
           href: blog.qmd
   ```

5. **Preview and deploy** as usual.

### Editing Existing Content

1. **Open the `.qmd` file** in your editor
2. **Make changes** to content or front matter
3. **Preview locally** to verify
4. **Commit and push** to deploy

## 🏗️ Build Process

### Local Rendering

```bash
# Render entire site
quarto render

# Render specific file
quarto render index.qmd

# Preview with live reload
quarto preview
```

### What Happens During Render

1. **Quarto reads** `_quarto.yml` configuration
2. **Processes** each `.qmd` file listed in `render:` section
3. **Converts** Markdown to HTML using Pandoc
4. **Applies** theme and styling (Cosmo/Darkly + custom CSS)
5. **Generates** navigation, TOC, and metadata
6. **Creates** RSS feed from blog posts
7. **Outputs** to `_site/` directory

### Build Artifacts

After rendering, `_site/` contains:
- `index.html` - Homepage
- `about.html` - About page
- `blog.html` - Blog listing
- `blog/posts/*.html` - Individual blog post pages
- `blog.xml` - RSS feed
- `site_libs/` - JavaScript, CSS, and other assets
- Other supporting files

## 🚀 Deployment Workflow

### Automatic Deployment (GitHub Actions)

The site deploys automatically using `.github/workflows/deploy.yml`:

**Trigger Events:**
- Push to `main` branch
- Manual trigger via GitHub Actions UI

**Workflow Steps:**
1. **Checkout**: `actions/checkout@v4` - Clone repository
2. **Setup Quarto**: `quarto-dev/quarto-actions/setup@v2` - Install Quarto
3. **Render**: `quarto render` - Build the site
4. **Upload**: `actions/upload-pages-artifact@v3` - Package `_site/` directory
5. **Deploy**: `actions/deploy-pages@v4` - Publish to GitHub Pages

**Permissions Required:**
```yaml
permissions:
  contents: read     # Read repository contents
  pages: write       # Write to GitHub Pages
  id-token: write    # OIDC token for deployment
```

**Concurrency Control:**
```yaml
concurrency:
  group: "pages"
  cancel-in-progress: false
```
Only one deployment runs at a time; subsequent deployments queue.

### Manual Deployment

**Via GitHub UI:**
1. Go to repository → **Actions** tab
2. Select **Deploy Quarto Site to GitHub Pages**
3. Click **Run workflow** → **Run workflow**

**Via Command Line:**
```bash
gh workflow run deploy.yml
```
(Requires GitHub CLI)

### Deployment Checklist

Before pushing to `main`:
- ✅ Preview changes locally (`quarto preview`)
- ✅ Verify no build errors (`quarto render`)
- ✅ Check blog listing includes new posts
- ✅ Test links and navigation
- ✅ Review generated HTML in `_site/` (optional)

After pushing:
- ✅ Monitor Actions tab for workflow status
- ✅ Verify deployment success (green checkmark)
- ✅ Visit live site to confirm changes
- ✅ Check RSS feed updates (`blog.xml`)

## 📋 File Naming Conventions

### Blog Posts
**Format:** `YYYY-MM-DD-descriptive-slug.qmd`

**Examples:**
- ✅ `2026-02-13-adding-documentation.qmd`
- ✅ `2026-02-14-matplotlib-contribution.qmd`
- ❌ `my-post.qmd` (missing date)
- ❌ `02-13-2026-post.qmd` (incorrect date format)

**Why This Format:**
- Ensures chronological sorting
- Makes dates immediately visible
- Prevents filename conflicts
- Aligns with common blogging conventions

### Pages
**Format:** `lowercase-with-hyphens.qmd`

**Examples:**
- ✅ `about.qmd`
- ✅ `contact.qmd`
- ✅ `my-projects.qmd`
- ❌ `About.qmd` (use lowercase)
- ❌ `my_projects.qmd` (use hyphens, not underscores)

### Directories
**Format:** `lowercase`, no special characters

**Examples:**
- ✅ `blog/`
- ✅ `images/`
- ❌ `Blog Posts/` (no spaces)

## 🎨 Style Guidelines

### Markdown Formatting

**Headers:**
```markdown
# Top-level heading (page title)
## Section heading
### Subsection heading
```

**Lists:**
```markdown
- Unordered list item
- Another item
  - Nested item

1. Ordered list item
2. Second item
```

**Links:**
```markdown
[Link text](https://example.com)
[Internal link](about.qmd)
```

**Code:**
````markdown
Inline `code` formatting

```python
# Code block with syntax highlighting
def example():
    return "Hello"
```
````

**Emphasis:**
```markdown
*italic* or _italic_
**bold** or __bold__
***bold italic***
```

### Quarto-Specific Features

**Callouts:**
```markdown
::: {.callout-note}
This is a note callout.
:::

::: {.callout-warning}
This is a warning.
:::

::: {.callout-tip}
This is a tip.
:::
```

**Code Execution (if using Python/R):**
````markdown
```{python}
#| echo: true
#| output: true

import numpy as np
print(np.array([1, 2, 3]))
```
````

**Cross-References:**
```markdown
See @fig-example for details.
```

**Recommended:**
```yaml

## 🧪 Testing Your Changes

### Local Testing

1. **Preview changes:**
   ```bash
   quarto preview
   ```
   - Opens browser with live site
   - Auto-reloads on file changes
   - Press `Ctrl+C` to stop

2. **Full render:**
   ```bash
   quarto render
   ```
   - Builds entire site
   - Check for errors in output
   - Inspect `_site/` directory

3. **Check specific issues:**
   - **Navigation:** Click all menu items
   - **Links:** Test internal and external links
   - **Responsive:** Resize browser window
   - **Dark mode:** Toggle theme switcher
   - **Code blocks:** Verify syntax highlighting and copy button
   - **Comments:** Check Utterances loads correctly

### Pre-Push Checklist

- [ ] `quarto render` completes without errors
- [ ] New content appears in blog listing (if applicable)
- [ ] All links work correctly
- [ ] Images load properly (if added)
- [ ] No broken references or 404s
- [ ] Front matter is valid YAML
- [ ] Content renders as expected
- [ ] Mobile view looks correct

### Debugging Common Issues

**Issue: Post doesn't appear in blog listing**
- Check: Date format is `YYYY-MM-DD`
- Check: `draft: false` (or omitted)
- Check: File is in `blog/posts/` directory
- Check: File has `.qmd` extension

**Issue: Render fails**
- Check: YAML front matter is valid (no tabs, proper indentation)
- Check: No unclosed code fences
- Check: All referenced files exist

**Issue: Styling looks wrong**
- Clear browser cache
- Check `styles.css` for syntax errors
- Verify `_quarto.yml` theme settings

**Issue: GitHub Actions deployment fails**
- Check Actions tab for error logs
- Verify `quarto render` works locally
- Check file permissions
